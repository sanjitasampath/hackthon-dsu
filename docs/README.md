# EcoSphere AI — AI-Powered Sustainable Campus Digital Twin

EcoSphere AI is a full-stack, hackathon-ready Digital Twin platform for a college campus. It combines simulated sensor streams, pure-function decision logic, real computer vision classification, unified incident lifecycle management, and AI-generated sustainability reports.

---

## Key Pillars & Modules

1. **Digital Twin Campus Map**
   - Interactive SVG map covering 11 shared campus locations (`CLASSROOM_101`, `CLASSROOM_102`, `AUDITORIUM_01`, `CORRIDOR_A1`, `LAB_CS_01`, `LAB_PHY_01`, `CANTEEN_01`, `LIBRARY_01`, `HOSTEL_01`, `SPORTS_01`, `ACADEMIC_BLOCK_01`).
   - Real-time color-coded severity reflections from the shared incident state.
   - Cross-module inspection drawer displaying live events, active incidents, and telemetry.

2. **Energy Engine (`/energy`)**
   - High-precision baseline vs. optimized load computation.
   - Dedicated zone models:
     - **Classrooms**: Timetable, occupancy sensing, enforced 5-minute grace period, manual override protection, and stale/missing data fail-safes.
     - **Auditoriums**: Staged load shutdown, occupancy counter verification, preserved emergency egress/lighting.
     - **Corridors**: Motion debouncing, daylight dimming hysteresis, and safety baselines.
     - **Laboratories**: Protected process-critical circuits, idle equipment management, and review flagging for unverified loads.
   - JSON audit export and event publishing.

3. **Waste Management — EcoSort AI (`/waste`)**
   - 8–10 monitored bins with configurable thresholds (<70% Normal, 70-84% Approaching, 85-94% Collection Recommended, >=95% Critical).
   - ESP32 + ultrasonic sensor ingestion endpoint (`POST /api/waste/sensor-readings`).
   - AI waste segregation with server-side Gemini Vision (or local client fallback), confidence scoring, campus disposal rules, and manual correction audit log.
   - Prioritized collection task creation and verification workflow.

4. **Shared Incident Management**
   - Centralized incident creation with deduplication key `(module, location_id, asset_id, issue_type)`.
   - Strict 5-stage lifecycle: `open` -> `acknowledged` -> `in_progress` -> `resolved_unverified` -> `verified_resolved`.
   - Resolution verification invariant: Requires fresh valid reading or documented manual inspection note.

5. **AI Sustainability Reports**
   - Daily and weekly summaries generated by Google Gemini when `GEMINI_API_KEY` is present.
   - Structured, rule-based fallback when offline or without API key.
   - Explicit distinction between confirmed facts, estimated savings, and hypothesis explanations.

## Stack & Directory Architecture

- **Frontend**: React 18, Vite, TypeScript, Tailwind CSS, Lucide icons, Recharts. (`/apps/web`)
- **Backend**: Node.js, Express, TypeScript, SQLite (`better-sqlite3`). (`/apps/api`)
- **Pure Logic Modules**: Independent engine packages in `/modules/energy` and `/modules/waste`.
- **Documentation & Contracts**: `/docs/SHARED_CONTRACT.md`, `/docs/README.md`, `/docs/ADDING_A_MODULE.md`.

## Getting Started

### 1. Environment Configuration
Copy `.env.example` in `apps/api` and `apps/web`:
```bash
# apps/api/.env
PORT=3001
CORS_ORIGIN=http://localhost:5173
GEMINI_API_KEY=your_key_here # Optional: enables Gemini Vision & AI reports

# apps/web/.env
VITE_API_URL=http://localhost:3001
```

### 2. Install & Run
```bash
npm install
npm run dev
```
- Frontend: `http://localhost:5173`
- Backend API: `http://localhost:3001`

### 3. Running Tests
```bash
npm run test
```
Runs unit test suites across modules for energy calculations, grace-period transitions, bin thresholds, and incident deduplication.
